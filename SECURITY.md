# Reporting security issues

Do not post passwords, tokens, original application bundles, user profiles or private logs in public issues.

For a suspected installer vulnerability, use GitHub's private vulnerability reporting if enabled, or describe only the affected version and a non-sensitive summary in an issue and ask for a private channel. Do not include an exploit involving another person's data.

The installer modifies local application resources and requires administrator privileges for deployment. Review scripts before running them. Only the build specified in `supported-build.json` is supported. Machine-generated translations are not a security policy, permission grant or advice about safe commands.
